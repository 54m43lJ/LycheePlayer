2. CONVENTIONS

↑

约定内容
IPC 通道命名 请求型为 域.动作（如 song.getUrls）；推送型为 域:事件（如 player:state、player:command）。
信封 所有请求型 IPC 返回 IpcResult<T>；主进程捕获一切异常并转为 IpcError，渲染进程不会收到被抛出的异常。
单位与 ID 类型 时长一律毫秒（number）；上游数字 ID 一律转为 string 后跨 IPC 传输。
凭证边界 凭证只存在于主进程 credential.ts；不得跨 IPC、写日志或进入渲染进程。存储实现与密钥环降级见 PROVIDER §2，用户侧边界见 USER §2。
上游隔离 上游原始 JSON 只存在于 api/ 层内部；离开该层的值必须是 §4.1 定义的内部模型。
错误映射 UpstreamError 直接保留其 code；超时 / 中止映射为 UPSTREAM_NETWORK；其他异常映射为 INTERNAL。
g_tk 计算 统一使用 hash33(value, 5381)。收藏签名写入的 g_tk 优先取 webCookies.skey → qqmusic_key → qm_keyst → musickey；g_tk_new_20200303 优先取 qqmusic_key → p_skey → skey → p_lskey → lskey → qm_keyst → musickey。资料 / OAuth 的既有 g_tk 规则不变，见 PROVIDER §1。
日志 日志只写主进程；不输出凭证、Cookie 与完整播放链接。
设置持久化 settings.set 以浅合并更新并立即写盘；加载时对未知值回退默认值。
工程常量 所有工程常量只在 shared/constants.ts 声明；模块只 import；派生常量使用表达式（如 PROBE_MAX_SONGS = PLAYLIST_PAGE_SIZE * PLAYLIST_PAGE_MAX），禁止模块内重复字面量。
缓存作用域 账号相关缓存键必须带 musicid 或 anonymous；退出登录清空歌单缓存与可用性缓存，音频体缓存按账号隔离保留。
启动参数 模块加载阶段由 applyFlagsFromDisk() 同步读取并应用 flags 文件，随后补内置默认；显式命令行最高，其次是文件、环境变量与内置默认。设置页使用异步 readFlagsFile / writeFlagsFile，只读写当前生效文件。
歌单分页 固定 50 首/页；补全串行、不取消；缓存始终是整份歌单快照，不按页落盘。
队列快照 只在“歌单快照 → 队列”边界按 playable !== false 过滤；队列本身不做检测或清理。完整加载、非 stale 且元数据探测完成后生成最终快照；之前只允许一次临时快照顶替。
可用性探测 探测只更新歌单歌曲元数据，不修改播放队列或当前播放；单次批量 PROBE_MIDS_MAX = 50，与歌单页大小对齐。
fixture 回放 测试默认不访问真实上游；请求匹配、脱敏、录制与更新流程见 test/fixtures/ 与 scripts/record-fixtures.mjs。
单实例 应用启动时请求单实例锁；第二个实例只唤醒并聚焦已有主窗口，不创建新进程。
导入省略 签名块省略 import 语句（如 electron 的 BrowserWindow），实现时按需引入。
  • 工程常量统一在 §4.50 声明；推荐值只以注释形式给出，不构成赋值；UI 视觉字面量见 USER §5。

stream 未命中，上游返回 200 或覆盖完整文件的 206 透传上游 200 / 206 Content-Type · Accept-Ranges · Content-Range（如有）· Content-Length（如有）· Cache-Control: no-store 是，边播边写缓存（受 audioCacheEnabled 控制） 只有 200 或 bytes 0-(total-1)/total 的完整 206 才落盘；上游无 body 时先读入内存。
stream 未命中，局部 Range 透传上游 206 同上游；至少保留 Content-Range / Content-Length / Accept-Ranges 否 每个 Range 独立转发，保证连续 seek 立即生效；局部 206 不落盘。
stream 上游错误（非 2xx / 206） 原始错误或 502 — 否 若已有缓存文件则回退 file 分支；否则返回“音频加载失败”。
未知 host 非 file / stream 400 — 否 无效音频地址。
  • 响应头契约：任何 206 都必须带 Content-Range 与 Content-Length，并声明 Accept-Ranges: bytes；所有响应设置 Cache-Control: no-store，避免 Chromium 缓存过期链接。
  • 上游请求带 Referer: https://y.qq.com/；请求中的 Range 原样透传。完整响应才缓存，局部响应不缓存。
  • resolveProtocolSource() 供 mpv 使用：file 解析为本地缓存路径；stream 优先返回已存在的缓存文件，否则返回 token 映射的上游 URL。HTML5 与 mpv 共用同一套 URL / token 语义，差异只在最后由谁加载。
