BUILD — Lychee Player

1. 环境要求

↑

项目要求
发行版Arch Linux x86_64；当前不支持其他发行版与 arm64。
构建工具base-devel、nodejs、npm。
运行期依赖GTK、libsecret、NSS、ALSA、D-Bus；可选系统 mpv（原生播放引擎）。

2. 开发运行

↑

npm ci
npm run dev
npm run typecheck
npm test
npm run test:watch
node scripts/probe.mjs
  • npm test 使用 fixture 回放，默认不访问真实上游；录制 fixture 需要显式开关，见 scripts/record-fixtures.mjs。
  • Vitest 运行在 Node 环境；导入链会经过 credential、audio-protocol 等主进程模块，因此测试用 vi.mock('electron') 提供最小 app / safeStorage / protocol / net。player / playlist 测试 mock AudioEngine、localStorage 与 window.lychee；test/replay.ts 用 Response 替换 fetch。
  • 测试不接入 CI；在本地或离线环境执行。测试文件树与覆盖范围见 CORE §1。

3. 构建

↑

npm run build

构建产物进入 out/；版本与许可证从 package.json 注入关于页。

  • electron-builder.yml 的关键字段：appId=io.github.lycheeplayer、productName=Lychee Player、directories.output=dist、directories.buildResources=build、linux.target=dir、linux.executableName=lychee-player、linux.icon=build/icon.png。
  • files 只包含 out/**/*、package.json 与 LICENSE；extraResources 把 resources/ 下的 icon.png / tray.png 复制到 process.resourcesPath，运行时图标读取该路径。

4. 打包

↑

npm run package:arch
dist/lychee-player-<version>-x86_64.tar.gz
dist/lychee-player-<version>-x86_64.tar.gz.sha256
dist/lychee-player/
├── lychee-player
├── resources/
├── LICENSE
├── flags.conf.example
├── lychee-player.desktop
└── lychee-player.png
  • electron-builder --linux dir 生成 dist/linux-unpacked 后由 scripts/package-arch.mjs 复制为 dist/lychee-player、补 LICENSE / 桌面文件 / 图标 / flags 示例，并生成 tar.gz 与 sha256。
  • electron-builder 26.x 会拒绝 linux.desktop 自定义字段，因此桌面文件不再写在 builder 配置里；packaging/arch/lychee-player.desktop 由打包脚本写入 tar 顶层。
  • mpris-service 的 abstract-socket 是原生模块，依赖 electron-builder 自带的 rebuild 步骤；打包机需要可用的编译工具链。
  • tarball 顶层固定为 lychee-player/，不包含源码、node_modules、测试或构建缓存。
  • 文件名版本与 package.json 一致，不带 v 前缀。

5. curl 安装

↑

# 默认安装 Preview 预发布
curl -fsSL https://raw.githubusercontent.com/54m43lJ/LycheePlayer/main/install.sh | sh
# 将来有稳定 Release 时指定版本
curl -fsSL https://raw.githubusercontent.com/54m43lJ/LycheePlayer/main/install.sh | sh -s -- --version v0.1.0
curl -fsSL https://raw.githubusercontent.com/54m43lJ/LycheePlayer/main/install.sh | sudo sh -s -- --system
# 覆盖仓库：LYCHEE_REPO=owner/repo curl ... | sh

# 开发测试：安装本地构建产物（需要同目录 .sha256）
./install.sh --local dist/lychee-player-0.1.0-x86_64.tar.gz
参数行为
--version <ver>默认 preview（预览版）；latest 解析最新稳定版；也可写 0.1.0 / v0.1.0。
--local <tarball>跳过下载，安装本地 tarball；要求同目录存在 .sha256。用于开发测试。
--prefix <dir>用户级安装目录；默认 ${XDG_DATA_HOME:-$HOME/.local/share}/lychee-player。
--system安装到 /opt/lychee-player，需要 root / sudo。
--uninstall删除程序、桌面文件与图标，保留设置与缓存。
--dry-run只打印动作，不写盘；默认 preview 不请求 API，--version latest 仍会请求 api.github.com。
  • 默认仓库为 54m43lJ/LycheePlayer，可用环境变量 LYCHEE_REPO=owner/repo 覆盖。
  • 当前只发布 Preview 预发布，不做版本管理；默认安装的就是 preview tag 的最新构建。
  • 默认用户级安装：程序目录 ${XDG_DATA_HOME:-$HOME/.local/share}/lychee-player，入口 ~/.local/bin/lychee-player，桌面文件与图标写入用户 XDG 目录。
  • 系统级安装：程序目录 /opt/lychee-player，入口 /usr/bin/lychee-player，桌面文件与图标写入 /usr/share。
  • 安装脚本强制校验 sha256sum；校验和缺失或不匹配时拒绝安装。也可先下载脚本检查再执行。
  • 安装时会把桌面项的 Exec / TryExec 改写为实际入口的绝对路径，避免 GUI 会话的 PATH 不包含 ~/.local/bin 时点击无效。

5.1 Preview Release 自动发布

↑

当前不做版本管理：每次 main 更新都会重建并覆盖同一个 Preview Release（tag preview，标记为 prerelease）。

# 正常开发：push main 即自动发布
git push origin main

# 手动重跑：GitHub Actions → Preview → Run workflow
  • .github/workflows/release.yml 在 main push 或 workflow_dispatch 时运行：npm ci → npm run package:arch → 覆盖 preview Release 的资产。
  • 产物固定为 lychee-player-preview-x86_64.tar.gz 与 .sha256，release 标记为 prerelease，不占用版本号；preview tag 始终指向最新 main 提交。
  • install.sh 默认下载该 tag 的固定资产；--version latest 保留给未来稳定版，当前没有稳定 Release。
  • workflow 需要仓库 Actions 启用，并允许 GITHUB_TOKEN 写 contents（workflow 已声明 permissions: contents: write）。
  • 需要稳定版时再改回 tag 驱动的版本化发布；当前不要创建 v* Release。
  • 只想本地测试时不用发 Release：npm run package:arch && ./install.sh --local dist/lychee-player-0.1.0-x86_64.tar.gz。

9. 故障排查

↑

症状处理
沙箱启动失败检查 chrome-sandbox 权限与用户命名空间；系统级安装按 §6 处理。
Wayland 显示异常在启动参数文件写 --ozone-platform=wayland 或 --ozone-platform=x11；见 §10。
密钥环未解锁 / “Decryption is not available”解锁 libsecret / gnome-keyring 后重启；密钥环不可用时登录被禁用。独立 Electron 调试脚本需显式设置 app.setName()、app.setPath('userData')，并执行 app.commandLine.appendSwitch('password-store', 'gnome-libsecret')，否则读不到 credential.bin。
调试端口连不上 / 第二个实例退出应用使用单实例锁：已有实例运行时，新进程只会唤醒旧窗口并退出。调试前先结束旧 PID，再带 --remote-debugging-port 启动；调试脚本固定读取 /json/list。
缺库安装 §1 运行期依赖。
curl / 校验和失败检查网络、Release 资产名与 sha256sum。默认安装 preview；没有该 Release 时先运行 Preview workflow。
桌面项点击没反应检查 ~/.local/share/applications/lychee-player.desktop 的 Exec 是否为绝对路径；重新运行安装脚本会按实际入口改写。可用 desktop-file-validate 检查语法。

10. 启动参数

↑

默认文件：$XDG_CONFIG_HOME/lychee-player/flags.conf；未设置 XDG_CONFIG_HOME 时为 ~/.config/lychee-player/flags.conf。每行一个参数，空行与 # 开头行忽略；--flags-file=<path> 可指定另一份文件。文件上限 STARTUP_FLAGS_MAX_BYTES = 8 KiB、STARTUP_FLAGS_MAX_LINES = 64，非 --name[=value] 形式的行会被过滤。

# Lychee Player 启动参数（每行一个）
--ozone-platform=wayland
--enable-wayland-ime
--password-store=gnome-libsecret
--autoplay-policy=no-user-gesture-required
  • 优先级：显式命令行 > flags 文件 > 环境变量 > 内置默认。文件在模块加载阶段同步读取并先应用，随后才补内置默认；appendSwitch() 会覆盖同名 switch，因此文件入口跳过 process.argv 已有的 switch，默认入口用 hasSwitch() 跳过已设置的 switch。
  • 内置默认只有 --password-store=gnome-libsecret 与 --autoplay-policy=no-user-gesture-required；--ozone-platform 的环境变量分支仍保持命令行 / 文件优先。
  • 设置页保存后下次启动生效，不热加载；不提供路径选择。

11. 存储

↑

用途位置 / 说明
歌单缓存userData/cache/playlist；每份歌单一个整份快照 JSON，complete 标记是否完整；超过 PLAYLIST_CACHE_MAX_BYTES 时按 mtime LRU 清理。
音频缓存userData/cache/audio/<musicid|anonymous>/<quality>/<songMid>.<mp3|flac>；总容量上限与 LRU 清理由 CORE 常量定义；退出登录不清空。
下载默认 ~/Music/Lychee Player（Settings.downloadDir 可改）；下载任务只保存在内存，应用重启后不恢复。.part 文件用于暂停 / 续传；仅本机个人使用。
mpv系统安装的 mpv 可执行文件；IPC socket 在 XDG_RUNTIME_DIR（缺失时用临时目录），权限 0600。
凭证 / 设置userData/credential.bin 由 safeStorage 加密，权限 0600；userData/settings.json 同样即时写盘。
