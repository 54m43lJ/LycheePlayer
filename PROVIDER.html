PROVIDER — Lychee Player

README USER CORE

1. TERMS

↑

术语定义
上游（Upstream） QQ 音乐的内容 CGI、登录服务、音频流服务器与封面图服务的统称。
musicu.fcg 上游统一的 JSON RPC 入口：请求体包含 comm 与 req_0（或 req），响应在 req_0 / req 中返回数据。
songMid 歌曲在 QQ 音乐的业务主键（字符串）。内容接口与播放链接请求均以它为标识。
mediaMid 音频文件级标识。付费歌曲的 mediaMid 可能与 songMid 不同；vkey 请求的 filename 必须使用它。
vkey 上游签发的音频流访问令牌，附于流 URL 查询参数，有时效；失效后需要重新获取。
purl vkey 接口返回的相对或绝对播放地址。其查询参数（guid / vkey / uin / fromtag 等）与令牌绑定，必须整体复用。
播放链接 由 purl 拼成的音频流 URL；相对路径拼为 https://ws.stream.qqmusic.qq.com/{purl}。
登录凭证（Credential） QQ 登录换取的访问凭据：musicid、musickey 及续期所需字段。仅主进程持有。
musicid QQ 音乐账号的数字标识；用于 Cookie、comm.uin、歌单与资料请求。
p_skey QQ 登录成功后写入 xlogin 会话的 Cookie，用于计算 OAuth g_tk 并完成 OAuth 授权。
g_tk（OAuth） 由 p_skey 经 hash33(p_skey, 5381) 计算的 CSRF 令牌，用于 OAuth authorize。
g_tk（资料） 由 musickey 经 hash33(musickey, 5381) 计算的 CSRF 令牌，用于用户资料请求。
xlogin QQ 官方扫码登录组件；登录页以独立视图加载，应用不接触用户密码。
  • 音质档位与请求 / 实际音质的用户语义见 USER §1；内部类型 Quality 见 CORE §4.1。
  • 歌词接口固定发送 g_tk=5381，不使用凭证派生值。

2. CONVENTIONS

↑

约定内容
契约范围 只记录应用实际消费的字段与方法；上游完整定义以官方文档为准。QQ 音乐未提供公开接口文档，本文档的权威来源是实际消费的请求与响应字段。
上游隔离 上游隔离规则见 CORE §2；本层只消费 CORE §4.1 定义的内部模型。
凭证注入 请求携带 Cookie：uin、qqmusic_uin、qm_keyst、qqmusic_key。凭证、Cookie 与完整播放链接不写入日志。
播放链接拼装 purl 为绝对 URL 时直接使用；为相对路径时只在前面拼 https://ws.stream.qqmusic.qq.com/，不重建查询参数。
音质回退 先尝试请求档位；该档位无 purl 时，再按 flac → 320k → 128k 顺序尝试其余档位（跳过已尝试的请求档位）；全部档位无链接时返回 NO_STREAM。
重试 HTTP 429、HTTP 非 2xx 与上游瞬时繁忙码（2001 / 104604）做短退避重试；连接失败 / 超时不重试，直接映射为 UPSTREAM_NETWORK。JSON 解析失败、响应结构缺失与未知错误码不重试，直接映射为 UPSTREAM_CHANGED。
错误映射 上游业务码、HTTP 状态与网络异常统一映射为内部 ErrorCode；映射表见 §4.2。
登录会话隔离 xlogin 使用独立 session 分区，只放行腾讯相关域名（qq.com / gtimg.cn / weixin.qq.com）导航与子窗口；登录发起前与结束 / 超时后各清理一次。
密钥环 凭证通过 Electron safeStorage（Linux 后端为 libsecret）加密后落盘；密钥环不可用时拒绝保存 / 加载凭证并禁用登录；旧明文仅在密钥环可用时迁移，否则拒绝登录，绝不退化为明文。
D-Bus MPRIS 依赖会话总线；D-Bus 不可用时 MPRIS 静默降级，不影响应用内播放。规范见 MPRIS Specification。

3. DIAGRAMS

↑

3.1 扫码登录协议

  • xlogin 组件加载官方登录页；应用不读取或保存用户密码。
  • Cookie 轮询路径必须同时看到 p_skey 与 p_uin / pt4_token / uin 之一，才进入 OAuth 换证，避免把未完成登录误判为成功。
  • xlogin 直接完成 OAuth 时，应用也可从 will-navigate / will-redirect / did-navigate 的 URL 捕获 code，直接进入换证。
  • OAuth 授权成功后，QQConnectLogin.LoginServer/QQLogin 返回 musickey 与续期字段；应用解析为 Credential 并在主进程入库。
  • 超时或失败返回 AUTH_EXPIRED，不保存凭证；登录视图在结束或超时后清理。
  • 扫码登录只走内嵌官方 xlogin 组件；Cookie 登录是兜底路径，见 §3.2。

3.2 Cookie 登录协议

  • Cookie 至少需要有效的 uin 与 qm_keyst；缺失或格式无效直接返回 AUTH_EXPIRED。
  • 应用用该凭证请求用户资料接口，g_tk 由 hash33(musickey, 5381) 计算；code === 0 视为登录态有效。
  • 验证成功后生成 Credential，保存在主进程；不保存浏览器 Cookie 原文。
  • 验证失败返回 AUTH_EXPIRED，提示用户重新获取 Cookie。

3.3 播放链接协议

  • 先通过 get_song_detail_yqq 获取 media_mid，再按请求音质拼出 vkey 的 filename。
  • vkey 请求使用进程级稳定 guid、歌曲 songmid 数组、对应 filename 数组与账号 uin。
  • midurlinfo[].purl 为空表示该曲在该档位无链接；按音质回退顺序继续尝试。
  • 音频流加载边界见 USER §3.1；主进程只经手链接字符串，不代理音频流。
  • vkey 失效时音频加载失败，界面提示“音频加载失败，可能链接已过期”；应用不会自动重新获取链接。

Credential musicid · musickey · expiredAtMs · refreshKey · refreshToken · accessToken · openid · unionid · loginType 项目归一化后的登录凭证；仅主进程持有，Credential 的续期字段不跨 IPC。
转换规则
QqSong → Song mid → songMid；id 转字符串 → songId；name ?? title → name；interval × 1000 → durationMs；singer[] 取 mid / name；album 取 mid / name；pay 映射为 PayInfo。
QqSong.pay → PayInfo price_album > 0 → album；否则 pay_play === 1 → vip；pay_play === 0 → free。
Quality → vkey filename 128k → M500{mediaMid}.mp3；320k → M800{mediaMid}.mp3；flac → F000{mediaMid}.flac。
QqVkeyData → UrlResult[] 按 songmid 匹配 purl；purl 非空则生成播放链接并记录实际档位；无链接的歌曲继续按回退顺序尝试。
purl → 播放链接 绝对 URL 原样使用；相对路径拼接 https://ws.stream.qqmusic.qq.com/，查询串保持不变。
QqPlaylistData → PlaylistDetail dirinfo → PlaylistMeta；songlist[] → Song[]；按 dirinfo.songnum 判断是否继续分页。
QqMineData → PlaylistMeta[] dissid ?? disstid ?? tid ?? dirId ?? id → id；名称、封面与歌曲数按字段回退链取值；过滤空 ID 与 0。
QqSearchData → SearchResult song.list → songs；singer.list / album.list / songlist.list 分别映射为 Singer[] / Album[] / PlaylistMeta[]；meta.sum ?? estimate_sum → total。
QqLyricResponse → Lyric lyric → lrc；trans 去空白后为空则 null；-1901 → 空歌词。
QqProfileResponse → UserProfile nick 缺省回退到 musicid；headpic 的 http: 改为 https:。
QqLoginPayload → Credential musicid 去前导 o 并校验为数字；expiredAtMs = musickeyCreateTime + keyExpiresIn × 1000（秒 / 毫秒时间戳自适应）；续期字段按存在性拷贝。
专辑 mid → 封面 URL https://y.gtimg.cn/music/photo_new/T002R{size}x{size}M000{mid}.jpg；size 为 300 / 500 等。
  • 内部目标模型 Song / PlaylistMeta / PlaylistDetail / SearchResult / Lyric / UserProfile / UrlResult 的定义见 CORE §4.1；Credential 的字段定义见 §4.3。
  • mediaMid、guid 与原始 purl 只在主进程 API 层内部存在，不进入 IPC 数据模型。
  • PayInfo 仅用于界面角标；实际可播性以 vkey 结果为准。

4.4 MPRIS

应用通过会话总线暴露 org.mpris.MediaPlayer2.lychee；D-Bus 是这里的传输层， 桌面环境作为调用方。以下为实际接线的协议子集。

字段含义

对象成员行为
RootIdentity / CanQuit / CanRaise / Raise / Quit应用名固定 Lychee Player；Raise 显示并聚焦主窗口；Quit 走正常退出生命周期。
PlayerPlaybackStatus / Metadata / Position由渲染进程发布的 player:state 驱动；元数据仅在切歌时更新。
PlayerPlay / Pause / PlayPause / Next / Previous / Seek / SetPosition转为内部 MprisCommand 推送回渲染进程执行；Stop 按暂停处理。
  • Seek / SetPosition 的偏移与目标位置均以微秒计；内部转换为毫秒后定位。
  • D-Bus / MPRIS 不可用时静默降级，不影响应用内播放；托盘不可用时同理。
