PROVIDER — Lychee Player

ABOUT USER CORE

1. TERMS

↑

术语定义
上游（Upstream） QQ 音乐的内容 CGI、登录服务、音频流服务器与封面图服务的统称。
musicu.fcg 上游统一的 JSON RPC 入口：请求体包含 comm 与 req_0（或 req），响应在 req_0 / req 中返回数据。
songMid 歌曲在 QQ 音乐的业务主键（字符串）。内容接口与播放链接请求均以它为标识。
mediaMid 音频文件级标识。付费歌曲的 mediaMid 可能与 songMid 不同；vkey 请求的 filename 必须使用它。
vkey 上游签发的音频流访问令牌，附于流 URL 查询参数，有时效；失效后需要重新获取。
purl vkey 接口返回的相对或绝对播放地址。其查询参数（guid / vkey / uin / fromtag 等）与令牌绑定，必须整体复用。
播放链接 由 purl 拼成的音频流 URL；相对路径拼为 https://ws.stream.qqmusic.qq.com/{purl}。
登录凭证（Credential） QQ 登录换取的访问凭据：musicid、musickey 及续期所需字段。仅主进程持有。
musicid QQ 音乐账号的数字标识；用于 Cookie、comm.uin、歌单与资料请求。
p_skey QQ 登录成功后写入 xlogin 会话的 Cookie，用于计算 OAuth g_tk 并完成 OAuth 授权。
webCookies 登录网页会话 Cookie 集合（p_skey / skey / qqmusic_key 等）。收藏签名写入需要它与 musickey 合并为请求 Cookie；只保存于主进程 Credential.webCookies，加密落盘，不跨 IPC。
g_tk（OAuth） 由 p_skey 经 hash33(p_skey, 5381) 计算的 CSRF 令牌，用于 OAuth authorize。
g_tk（资料） 由 musickey 经 hash33(musickey, 5381) 计算的 CSRF 令牌，用于用户资料请求。
g_tk（签名写入） g_tk 优先取 webCookies.skey → qqmusic_key → qm_keyst → musickey；g_tk_new_20200303 优先取 qqmusic_key → p_skey → skey → p_lskey → lskey → qm_keyst → musickey。全部经 hash33(value, 5381)。
xlogin QQ 官方扫码登录组件；登录页以独立视图加载，应用不接触用户密码。
推荐接口 每日推荐走 RecommendFeed / get_recommend_feed 的 subtype:510 卡片；专属雷达走 TrackRelationServer / GetRadarSong；猜你喜欢走 mb_track_radio_svr / get_radio_track。
收藏接口 SongFavRead / IsSongFanByMid 读取红心状态；PlaylistDetailWrite / AddSonglist | DelSonglist 经 zzc 签名 + ag-1 加密通道写入 201 目录。
歌单写入接口 PlaylistBaseWrite 负责创建 / 改名 / 删除；PlaylistDetailWrite 负责增删歌曲。普通歌单走明文 musicu 通道，201 目录走签名加密通道。
201 目录 / songType dirId: 201 是“我喜欢”歌单的固定目录；写入时必须使用歌曲详情的真实 songType，不能用 0 或类型 1 兜底，否则可能返回 80105 或写入用户不可见的隐藏记录。
MV 接口 搜索复用 search_type:4；详情走 MvService.MvInfoProServer / GetMvInfoList；取流走 gosrf.Stream.MvUrlProxy / GetMvUrls。
  • 音质档位与请求 / 实际音质的用户语义见 USER §1；内部类型 Quality 见 CORE §4.1。
  • 歌词接口固定发送 g_tk=5381，不使用凭证派生值。

2. CONVENTIONS

↑

约定内容
契约范围 只记录应用实际消费的字段与方法；QQ 音乐未提供公开接口文档，本文档的权威来源是实际消费的官方可访问接口（无公开文档）。
上游隔离 上游隔离规则见 CORE §2；本层只消费 CORE §4.1 定义的内部模型。
凭证注入 请求携带 Cookie：uin、qqmusic_uin、qm_keyst、qqmusic_key；收藏签名写入前先合并 Credential.webCookies（如 p_skey / skey），同名时以凭证字段为准。凭证、Cookie 与完整播放链接不写入日志。
收藏写入 201 目录的 AddSonglist / DelSonglist 必须走 u6.y.qq.com/cgi-bin/musics.fcg 的 zzc 签名 + AES-128-GCM ag-1 通道；旧 fcg_music_add2songdir.fcg 在最小 Cookie 下返回 403 invalid request / no permit，不再使用。写后必须读回状态与成员可见性。
播放链接拼装 purl 为绝对 URL 时直接使用；为相对路径时只在前面拼 https://ws.stream.qqmusic.qq.com/，不重建查询参数。
音质回退 先尝试请求档位；该档位无 purl 时，再按 flac → 320k → 128k 顺序尝试其余档位（跳过已尝试的请求档位）；全部档位无链接时返回 NO_STREAM。
限速 应用侧所有主动发出的上游请求共用一个全局令牌桶（持续速率与突发容量见 CORE §4.50），OAuth authorize 与收藏签名写入同样受控；批量探测按批串行，不并发轰炸。
重试 HTTP 429、HTTP 非 2xx 与上游瞬时繁忙码（2001 / 104604）做短退避重试；连接失败 / 超时不重试，直接映射为 UPSTREAM_NETWORK。JSON 解析失败、响应结构缺失与未知错误码不重试，直接映射为 UPSTREAM_CHANGED。
错误映射 上游业务码、HTTP 状态与网络异常统一映射为内部 ErrorCode；映射表见 §4.2。
评论读取 固定匿名发送，不携带凭证；单页条数不超过 25，应用固定 20。条数与上游参数见 §4.1，内部签名见 CORE §4.15。
VIP 状态 仅用于不可播文案判断；未登录或接口失败按非 VIP 处理，缓存见 CORE §4.13。
登录会话隔离 xlogin 使用独立 session 分区，只放行腾讯相关域名（qq.com / gtimg.cn / weixin.qq.com）导航与子窗口；登录发起前与结束 / 超时后各清理一次。
密钥环 凭证通过 Electron safeStorage（Linux 后端为 libsecret）加密后落盘；密钥环不可用时拒绝保存 / 加载凭证并禁用登录；旧明文仅在密钥环可用时迁移，否则拒绝登录，绝不退化为明文。
D-Bus MPRIS 依赖会话总线；D-Bus 不可用时 MPRIS 静默降级，不影响应用内播放。规范见 MPRIS Specification。

3. DIAGRAMS

↑

3.1 扫码登录协议

  • xlogin 组件加载官方登录页；应用不读取或保存用户密码。
  • Cookie 轮询路径必须同时看到 p_skey 与 p_uin / pt4_token / uin 之一，才进入 OAuth 换证，避免把未完成登录误判为成功。
  • xlogin 直接完成 OAuth 时，应用也可从 will-navigate / will-redirect / did-navigate 的 URL 捕获 code，直接进入换证。
  • OAuth 授权成功后，QQConnectLogin.LoginServer/QQLogin 返回 musickey 与续期字段；应用解析为 Credential 并在主进程入库。扫码成功后会在清理 lychee-xlogin 分区前抓取 qq.com 网页 Cookie（p_skey / skey 等），写入 Credential.webCookies。
  • 超时或失败返回 AUTH_EXPIRED，不保存凭证；登录视图在结束或超时后清理。
  • 扫码登录只走内嵌官方 xlogin 组件；Cookie 登录是兜底路径，见 §3.2。

3.2 Cookie 登录协议

  • Cookie 至少需要有效的 uin 与 qm_keyst；缺失或格式无效直接返回 AUTH_EXPIRED。
  • 应用用该凭证请求用户资料接口，g_tk 由 hash33(musickey, 5381) 计算；code === 0 视为登录态有效。
  • 验证成功后生成 Credential，保存在主进程；Cookie 登录会保留完整 Cookie jar，其中 p_skey / skey 等网页会话字段写入 Credential.webCookies，与 musickey 一起加密保存，仅主进程使用。
  • 验证失败返回 AUTH_EXPIRED，提示用户重新获取 Cookie。普通内容请求只依赖 musickey；收藏签名写入还依赖 webCookies，缺失时可能返回 80105。

3.3 播放链接协议

  • 先通过 get_song_detail_yqq 获取 media_mid，再按请求音质拼出 vkey 的 filename。
  • vkey 请求使用进程级稳定 guid、歌曲 songmid 数组、对应 filename 数组与账号 uin。
  • midurlinfo[].purl 为空表示该曲在该档位无链接；按音质回退顺序继续尝试。result 同时返回授权结果码，应用会保留每个档位最后一次结果，用于全批量失败时区分权限、链路与下架。
  • 经典入口为 vkey.GetVkeyServer / CgiGetVkey；该入口返回 104009（invalidq）时，应用会再尝试当前维护的 music.vkey.GetVkey / UrlGetVkey 一次。两个入口都返回 104009 时按网络 / VPN / 代理出口问题处理，不再当作接口结构变化或单曲下架。
  • 音频流端点与 vkey / purl 契约不变；应用侧加载边界见 USER §3.1。
  • 上游音频流必须兼容 Range：应用会把浏览器的 Range 原样转发，并优先使用上游返回的 206 / Content-Range / Accept-Ranges。若上游忽略 Range 返回 200，代理按完整响应处理并缓存；局部 206 不缓存。
  • vkey 失效或流中断时，播放器对同一歌曲最多每 30 秒自动重新取一次链接并从原位置继续；再次失败才提示“音频加载失败，可能链接已过期”。PROVIDER 不再承诺“不会自动重新获取链接”。

3.4 QQ Web 签名 / 加密协议（收藏写入）

201 目录的收藏写入使用 QQ 官网 Web 通道；算法参考 MIT 项目 jixunmoe/qmweb-sign，使用 Node 内置 crypto 实现，不新增依赖。

步骤规则
请求体 JSON.stringify({ comm, playlist: { module: 'music.musicasset.PlaylistDetailWrite', method: 'AddSonglist' | 'DelSonglist', param } })；签名、加密与发送使用同一份 UTF-8 字符串。
zzc 签名 对请求体做 SHA1，取大写十六进制 hash；sign = 'zzc' + pick([23,14,6,36,16,7,19]) + middle + pick([16,1,32,12,19,27,8,5])，最终转小写。pick 按索引取 hash 字符；middle 为 SCRAMBLE 与 hash 每字节 XOR 后 Base64，并删除 + / =。
加密 AES-128-GCM，固定 16 字节请求密钥 bd305f10d0ff74b6ef54dab835b5e1cf，每次请求随机 12 字节 IV；发送体为 base64(iv || ciphertext || authTag)。
端点 POST https://u6.y.qq.com/cgi-bin/musics.fcg?encoding=ag-1&sign=<zzc签名>&_=<时间戳>
请求头 Referer: https://y.qq.com/、桌面 Chrome UA、合并后的 Cookie（含 webCookies）、Content-Type: text/plain、Accept: application/octet-stream。
响应解码 对响应字节逐字节 XOR RESPONSE_KEY（按 21 字节循环），再按 UTF-8 解析 JSON；解析失败映射为 UPSTREAM_CHANGED。
错误 业务码 2001 / 104604 做短暂重试；1000 / 301 映射 AUTH_EXPIRED；80105 提示重新登录同步网页会话；1101 表示该歌曲暂不支持收藏。
  • comm 至少包含 uin、format、ct、cv、authst、platform、g_tk、g_tk_new_20200303；Cookie 与 key 均由主进程凭证生成，不进入渲染进程。
  • 推荐、歌单创建 / 改名 / 删除与 MV 接口仍未完成 fixture 验证。

  • 普通内容 CGI 不需要额外签名；收藏写入必须使用 §3.4 的 zzc 签名 + ag-1 加密通道；g_tk 还用于 OAuth 授权、歌词与用户资料请求。

  • “我喜欢”歌单读取使用 CgiGetDiss 的 disstid:0 + dirid:201；普通歌单仍使用 disstid。上游单次最多返回 100 首，应用固定 50 首/页。
  • 推荐、歌单写入与 MV 的方法 / 参数已按真实请求固定；内部调用路径与错误处理见 CORE §4.53 / §4.55 / §4.56。

转换规则
QqSong → Song mid → songMid；id 转字符串 → songId；name ?? title → name；interval × 1000 → durationMs；singer[] 取 mid / name：只要 name 非空就保留，mid 允许为空，仅丢弃 name 为空的成员；album 取 mid / name；pay 映射为 PayInfo。
QqSong.pay → PayInfo price_album > 0 → album；否则 pay_play === 1 → vip；pay_play === 0 → free。
QqSong.file.size_* → 候选最高档 size_flac > 0 → flac；否则 size_320mp3 > 0 → 320k；否则 128k；字段缺失时由 CORE 逐档探测。
Quality → vkey filename 128k → M500{mediaMid}.mp3；320k → M800{mediaMid}.mp3；flac → F000{mediaMid}.flac。
QqVkeyData → UrlResult[] 按 songmid 匹配 purl；purl 非空则生成播放链接并记录实际档位；无链接的歌曲继续按回退顺序尝试。
purl → 播放链接 绝对 URL 原样使用；相对路径拼接 https://ws.stream.qqmusic.qq.com/，查询串保持不变；随后由主进程包装为 lychee-audio://stream/<token>，不把上游链接交给渲染进程。
QqFavoriteData → FavoriteState[] 按请求 v_songMid 顺序读取 m_fan[mid]；未登录或异常按未收藏处理，缺失字段视为响应不完整。
QqTrackIdentity → 写入参数 id 转十进制字符串校验 → songId；type 原样作为 songType。写入体为 { dirId: 201, v_songInfo: [{ songId: Number(songId), songType }] }。
QRC 密文 → 逐字歌词 hex → 3DES-ECB（des-ede3，固定密钥，setAutoPadding(false)）→ inflateSync → LyricContent XML → 逐字行；失败时回退 LRC。
QqPlaylistData → PlaylistDetail dirinfo → PlaylistMeta；songlist[] → Song[]；按 dirinfo.songnum 判断是否继续分页。
QqMineData → PlaylistMeta[] dissid ?? disstid ?? tid ?? dirId ?? id → id；名称、封面与歌曲数按字段回退链取值；dirId === 201 → kind='favorites'、id='liked'；listMine 结果 editable=true，搜索/公开歌单 editable=false；过滤空 ID 与 0。
QqSearchData → SearchResult song.list → songs；singer.list / album.list / songlist.list 分别映射为 Singer[] / Album[] / PlaylistMeta[]；meta.sum ?? estimate_sum → total。
QqArtistInfo → ArtistDetail Fsinger_mid / Fsinger_name → mid / name；singerBrief → description；total_song / total_album → 计数；封面由 mid 拼 T001R500x500。
QqArtistSongData → ArtistDetail.songs 优先读取 req_0.data.songList[].songInfo 与扁平 totalNum；缺失时回退 singerSongList.data 包裹；songInfo → Song，totalNum → total；hasMore 按已载入数与总数比较。
QqAlbumDetail → AlbumDetail basicInfo.albumName / publishDate / desc → 对应字段；singer[] → Singer[]；封面由 mid 拼 T002R500x500。
QqAlbumSongData → AlbumDetail.songs songList[].songInfo → Song；totalNum → total；hasMore 按已载入数与总数比较。
QqRecommendFeedData → 每日推荐 在 v_shelf[].v_niche[].v_card[] 中取唯一 subtype:510 且 time 为上海当天的卡片，id 作为动态歌单 ID。
QqRadarData → Song[] VecSongs[].Track 解包后按 QqSong → Song 映射；HasMore 控制翻页。
QqRadioData → Song[] tracks[] 已是扁平歌曲模型，按 QqSong → Song 映射并按 mid 去重。
QqPlaylistWriteResult → PlaylistMeta retCode === 0 且 result.dirId / result.tid 为正整数才成功；dirName 回填名称，editable=true。
QqMvSearchData → MvSummary[] v_id → mvId；mv_name → name；singer_list[].name 拼接 → singerName；mv_pic_url → coverUrl。
QqMvInfo → MvDetail mvlist[0]：vid / name / cover_pic / desc / pubdate 映射；singers[].name 拼接为 singerName。
QqMvUrlData → MvStream mp4[].filetype 10 / 20 / 30 → sd / hd / fhd；可播地址取 freeflow_url，无地址即该档不可用。
QqCommentLikeResult → CommentLikeResult code / subcode 均为 0 才成功；type 3 → liked=true，4 → liked=false；点赞数由读回评论校正。
QqLyricResponse → Lyric qrc 存在 → format: 'qrc'、text: qrc；否则 format: 'lrc'、text: lyric；trans 去空白后为空则 null；-1901 → 空歌词。
QqCommentList → CommentPage CmId → id；Nick → nickname；Avatar 的 http: 改为 https:；Content → content；PubTime 秒 / 毫秒自适应后 → createdAtMs；PraiseNum → likedCount；ReplyCnt → replyCount；Total → total；HasMore → hasMore。
QqProfileResponse → UserProfile nick 缺省回退到 musicid；headpic 的 http: 改为 https:。
QqLoginPayload → Credential musicid 去前导 o 并校验为数字；expiredAtMs = musickeyCreateTime + keyExpiresIn × 1000（秒 / 毫秒时间戳自适应）；续期字段按存在性拷贝。
专辑 mid → 封面 URL https://y.gtimg.cn/music/photo_new/T002R{size}x{size}M000{mid}.jpg；size 为 300 / 500 等。
  • 内部目标模型 Song / PlaylistMeta / PlaylistDetail / SearchResult / Lyric / Comment / CommentPage / UserProfile / UrlResult / ArtistDetail / AlbumDetail 的定义见 CORE §4.1；Credential 的字段定义见 §4.3。
  • mediaMid、guid 与原始 purl 只在主进程 API 层内部存在，不进入 IPC 数据模型。
  • PayInfo 仅用于界面角标；实际可播性以 vkey 结果为准。
  • 收藏写入的 songType 必须来自详情接口真实字段；webCookies 与签名密钥只存在于主进程，不写日志、不跨 IPC。

  'mpris:trackid': string;
  'mpris:length': number;
  'mpris:artUrl': string;
  'xesam:title': string;
  'xesam:artist': string[];
  'xesam:album': string;
}
字段含义
Position当前播放位置，单位微秒。
Volume播放器音量，0–1，可写。
LoopStatus循环模式：sequence → None；repeat-all / shuffle → Playlist；repeat-one → Track。可写。
Shuffleshuffle 模式为 true，其余为 false。可写。
mpris:trackid曲目对象路径：/org/mpris/MediaPlayer2/track/{songMid}。
mpris:length曲目时长，单位微秒。
mpris:artUrl专辑封面 URL。
xesam:title歌曲名。
xesam:artist歌手名数组。
xesam:album专辑名。
对象成员行为
RootIdentity / CanQuit / CanRaise / Raise / Quit应用名固定 Lychee Player；Raise 显示并聚焦主窗口；Quit 走正常退出生命周期。
PlayerPlaybackStatus / Metadata / Position / Volume / LoopStatus / Shuffle由渲染进程发布的 player:state 驱动；元数据仅在切歌时更新。
PlayerPlay / Pause / PlayPause / Next / Previous / Seek / SetPosition转为内部 MprisCommand 推送回渲染进程执行；Stop 按暂停处理。
PlayerVolume / LoopStatus / Shuffle可写属性；变更转为 setVolume / setLoopStatus / setShuffle 命令回送渲染进程。
  • Seek / SetPosition 的偏移与目标位置均以微秒计；内部转换为毫秒后定位。
  • D-Bus / MPRIS 不可用时静默降级，不影响应用内播放；托盘不可用时同理。
  • LoopStatus 与 Shuffle 的写入同步更新播放模式；Volume 写入同步更新播放器音量。
  • 入站命令如何转成 MprisCommand、播放状态如何发布，见 CORE §5.6；类型定义见 CORE §4.1。
  • 可用 playerctl -p lychee 验证总线上暴露的成员。
