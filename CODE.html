2. CONVENTIONS

约定内容
错误处理主进程所有 IPC handler 经 envelope 包裹，异常一律转为 IpcError 信封返回，不向渲染进程抛异常。
上游响应上游原始 JSON 只存在于 api/ 层内部；离开该层的值必须是 ARCHITECTURE §4.3 的形态。
日志日志只写主进程；不输出凭证、Cookie 与完整播放链接。
导入省略本文档签名块省略 import 语句（如 electron 的 BrowserWindow），实现时按需引入。

interface LoginEvents {

  • createQrKey 返回二维码图片（data URL）并在主进程内启动轮询，状态经 login:status 推送（ARCHITECTURE §3.2）；应用内二维码为实验路径。

  • refreshSession 用 refresh_token 调用 music.login.LoginServer/Login 换新 musickey，有效期约 72 小时；启动后与每 30 分钟检查。

4. Call stack tree

4.1 启动

index::bootstrap()
├── settings::loadSettings()
├── credential::loadCredential()
├── ipc::registerIpc()
│   └── api/login::initLoginEvents(events)          // login:status 推送与凭证入库回调
├── integration/mpris::initMpris(sendPlayerCommand)
├── integration/tray::initTray(actions)
├── index::createMainWindow()
└── api/login::refreshIfNeeded()                    // 启动检查一次，此后定时器每 30 分钟触发
  • loadCredential 失败按未登录继续，不阻塞启动。
  • sendPlayerCommand 由 ipc.ts 提供，把 MPRIS / 托盘命令转成 player:command 推送。
  • 模块加载阶段（bootstrap() 之前）固定启动参数（字面量按项目决定显式记录）：--password-store=gnome-libsecret 固定 libsecret 后端；检测到 WAYLAND_DISPLAY 时追加 --ozone-platform=wayland 与 --enable-wayland-ime，可由 LYCHEE_OZONE_PLATFORM 或显式命令行覆盖。

4.2 播放单曲

stores/player::playSong(song)
├── window.lychee.song.getUrls([song.songMid], requestedQuality)   // settings 默认音质或播放条强制档
├── 判断 url === null → 提示 NO_STREAM 后返回
├── audio/engine::loadAndPlay(url)                  // AudioEngine 接口，当前为 HTML5 Audio 实现
├── AudioEngine 事件 onTimeUpdate / onEnded → send player:state
│   └── integration/mpris::publishState(state)
└── 事件 onEnded → queue 取下一曲 → stores/player::playSong(next)
  • 音频流由渲染进程直接加载，主进程只经手链接字符串。
  • MPRIS 反向控制：D-Bus → mpris.ts → ipc.ts → player:command 推送 → playerStore 执行。

4.3 退出

app::before-quit
├── index::clearInterval(refreshTimer)
├── integration/mpris::publishState(null)
├── integration/tray::destroyTray()
├── settings::saveSettings(current)                 // 兜底，不等待完成
└── 窗口销毁 → 进程退出
  • 凭证默认保留，支持下次自动登录；清除仅由 login.logout() 触发。
  • closeToTray 生效时关闭窗口仅隐藏，before-quit 只在托盘退出时触发。
